# Aspera 服务器登记与首次 SSH 连接

[English](guide.md) | 中文

## 变更

Aspera 允许从本机服务器列表移除空闲调度主机。每个新实验从本次参与节点里显式选择调度主机；历史实验保留已保存的调度主机、Session 和远端发布。待完成任务、命令或接管结果未确认仍会阻止移除。远端文件保留，不再引用的自有凭据移除。

本机连接检查和准备采用首次使用时信任，自动登记首次遇到的 SSH 主机密钥。已有或已撤销的密钥不会被替换。密码登录和委派节点连接继续严格核对密钥。连接检查只修改本地信任记录并读取远端状态，不调用模型或安装依赖。自定义 `FleetDriver` 提供方需实现 `prepareSshHostKey`。

## 迁移

1. 部署匹配的 Aspera 应用和生成的客户端，保留历史实验及远端发布目录。已有 fleet 记录仍可读取，远端提交协议和 Session 格式不变。
2. 对空闲的服务器登记使用**删除服务器**。移除被阻止时，先停止待完成任务或核对其结果。创建每个实验时指定调度主机，已有实验继续使用原目标。参阅[管理功能升级说明](../aspera-management/guide.zh.md)。
3. 对新配置的服务器使用**检查连接**。首次主机密钥保存在所选 `known_hosts` 文件中。核对连接结果及依赖诊断。密钥变化或撤销时需调查原因，自动登记不会清除该警告。
4. 更新自定义 `FleetDriver` 实现，提供 `prepareSshHostKey(target, signal?)`。参阅[派发参考](../../../../extensions/aspera/packages/dispatch/README.zh.md)。
