# Aspera 阶段模型与管理界面

[English](guide.md) | 中文

## 变更

Aspera 保持 `0.1.1`，DSH 保持 `0.2.0-rc.2`。新实验使用协议及存储第 4 代，准备、计划和执行各自拥有固定提供商设置及私有凭据快照。创建接口要求显式传入 `models`，派发工具要求 `models_json`。缺少凭据或认证方式不受支持时拒绝提交，不切换到 DeepSeek。

发布文件包含两个固定版本的包补丁，用于侧栏分组插槽和现有设置命令的调用。生成的 Remote 使用方及桌面安装必须采用完整的同一构建。Agent 记录使用阶段／Session／序号游标，进程日志使用节点／命令／输出流／代次游标。

## 迁移

1. 旧实验运行期间保留原应用目录及远端发布文件。任务结束并确认进程清理后，才能升级节点控制服务；不能同时让两个控制版本使用同一状态目录。
2. 安装完整的新构建，包括 `patches/` 和锁文件。执行固定依赖安装，独立维护的使用方重新生成 Remote。检查构建标识，应用版本号不足以区分这些构建。
3. 打开 **Aspera 模型设置**管理已有 DSH 账户，创建实验前选择三个阶段的 Agent 模型。API 地址、选项及凭据独立保存，之后修改全局配置不影响它们。
4. 将第 1～3 代未完成的准备记录复制为新实验。历史记录保留原始版本、摘要及模型信息，不把旧回执中的 `0.2.0` 改写为其他版本。
5. 在实验详情核对模型选择，分别查看准备、计划及执行记录。浏览器记录及回执不能包含原始密钥或提供商请求头。归属及兼容方式见[状态与接口说明](../../../../extensions/aspera/docs/state-and-api.zh.md)。
