# 受管训练环境

[English](managed-environments.md) | 中文

## 摘要

每个实验节点登记独立的 Python 解释器、依赖元数据及经过核验的包引用。安装材料摘要、来源和构建身份、Python ABI 与 wheel 平台标签一致的包，在所选数据盘共享不可变内容。已有环境、发布、模型、数据集和结果继续保留。

[服务器存储与固定材料](storage-governance.zh.md) 定义账号视角盘点、已释放历史环境借用、逐卷容量预留、历史重复材料清理及固定模型／数据获取。这些工具共用已有准备与执行 Agent；全部验收由程序完成。

## 创建与验收

准备 Agent 按固定发布清单的 `asperaEnvironmentTools.uvVersion` 安装 Python 和固定版本 uv，程序探测并保存实际可执行路径。执行 Agent 在已分配节点调用 `inspect_experiment_environment`，再以环境名称、UUID 操作 ID 及 `create`、`install`、`verify` 或 `make-writable` 请求 `prepare_experiment_environment`。默认环境为 `training`；额外环境需要用途说明及独立相对目录。请求不能更改服务器归属、设备授权、共享包库或进程 ID。

`create` 安装提交的依赖要求，并与已有环境的原直接要求合并。实际版本满足要求时原地复验；约束冲突在发布前失败并保留原代次。`install` 通过私有新代次明确替换直接依赖要求。原始请求和生效要求分别记录。空要求只创建经过验收的基础解释器。uv 解析带摘要的依赖，构建仅在沙箱私有目录进行，共享材料只读挂载。安装指定绝对解释器并禁用用户级包；前缀不正确时失败，不转入 `.local`。

每次安装先核对当前环境、共享包、已验证材料和历史 wheel，再获取缺失依赖。兼容的未变环境直接复验，不创建另一套 venv。锁定结果按需求、解释器、平台和 uv 身份在失败后保留。每个操作保存带时间的复用计划，包括决定、下载字节、复用内容、预计峰值和实际新增空间。峰值计入已获取的私有工具/材料、后续展开和文件元数据；可用空间检查仅预留剩余需求及安全余量。链接命中的包不计入整包安装预算。

程序核验包内容摘要、实际解释器前缀、用户级包禁用状态、指定导入及 `uv pip check`。请求的 CUDA 验收使用环境内的 torch 解释器；节点获得 NVIDIA GPU 设备授权且环境包含 torch 时，即使请求遗漏该项也必须核验 CUDA。导入、依赖或所需 CUDA 检查失败，均不能发布就绪环境。

`prepare_experiment_environment` 保持串行工具未结束，直到节点确认最终回执、进程组退出及准入释放。认证的 `environment-status` 只读取当前实验及操作，不扫描包内容。原期限在重连和重复调用后保持不变；提交回复丢失时只查询状态，不再次提交。默认配置为 `operationPollIntervalMs: 1000`、`timeoutMs: 1800000`、`readTimeoutMs: 30000`、`stopTimeoutMs: 30000` 和 `operationReconnectTimeoutMs: 60000`。超时由节点停止操作，取消信号传入等待和网络请求。退出未确认或连接恢复预算用尽时返回结果未决，并保留保护。`inspect_experiment_environment` 可传入 `operation_id` 进行轻量读取。

程序生成并执行 uv 命令。专属安装工具环境包含固定的 `asperaEnvironmentTools.pipVersion`，其中标准 wheel、标签和依赖解析器与训练解释器的 Python 版本及 ABI 一致。训练环境不自动填入种子包，只有明确请求或依赖需要时才安装 pip、setuptools、packaging 和 wheel。下载与构建使用只读的安装工具内容，小型安装工具文件独立复制，避免通过可写构建缓存中的别名修改工具。程序的 Python 调用使用隔离的模块查找，导入复验同样遵循此规则；依赖安装目标仍为训练环境。工具临时占用纳入空间预算及 `installerTemporaryBytes`；要求不变的复验继续保留就绪环境。

wheel 材料保留原文件名。安装工具中的标准 wheel/tag 解析器核验包名、版本、构建标识和完整标签。已验证的历史材料若曾丢失文件名标签，在私有安装目录按目标优先级选择包内声明的标签建立别名。解析目录、完整 wheel 安装及共享包元数据安装统一使用这些别名；原内容和索引保持不变。摘要将材料绑定到锁定来源，不兼容或损坏材料仍被拒绝。

已认证的提交 wheel 可通过 `name @ file://.../inputs/file.whl` 请求。节点将原输入摘要绑定实验，任意地址仍不能复用。仅顶层命名元数据或已声明 wheel 标签冲突时，Agent 可选择程序生成的修复计划并设置 `repairWheelMetadata: true`。程序创建独立构建身份，保留原件，并核对代码、动态库和依赖元数据全部未变；仍须通过目标兼容性、依赖、导入及 CUDA 检查，修正标签不能单独证明运行兼容。

安装进程在隐藏共享库后，仅通过只读挂载访问逐一核验的输入 wheel。解析及安装可以读取保留的派生材料，不开放其他包或写权限；原文件地址和锁定身份保持稳定。

完成实验前重新核对实际包内容与最近验收摘要。普通命令修改已分离文件后，需要再执行 `verify` 才能完成；保留的就绪清单不能代替该项检查。

安装、操作查询和恢复均在 `storageToolResultBytes` 内返回完整 JSON。小结果保留原字段；大结果内联保留操作结果、解释器路径、验收、清理／恢复状态、期限及复用统计，完整包清单和诊断保存在实验授权范围内的快照中。将返回的 `details` 对象作为 `details_json` 传给 `inspect_experiment_environment`，再沿字段或数组分页读取。详情保留原时间，不重新扫描或修改环境。这些摘要不能代替节点原始回执和完成检查。

<a id="reuse-and-changes"></a>
## 复用与修改

服务器专属共享包库位于 `<namespaceRoot>/packages-v1`。发布前核对 wheel RECORD 摘要和实际安装文件，再建立包引用。同盘优先使用硬链接；失败后实际尝试文件系统克隆接口并核对内容，不支持克隆时，仅在空间预算通过后独立复制。环境清单记录方式、原因、预计普通复制字节数及实际新增空间。已分配字节按文件身份去重统计，写时复制节省量明确标为估计。

已验证 wheel 在环境复验前进入按内容摘要登记的 `materials` 材料库，完整材料在其他下载或导入失败后保留。共享包使用只含元数据和声明脚本的缩减 wheel，由固定 uv 生成专属元数据和入口，程序再链接已验证内容并更新 RECORD。需要其他 wheel 数据区的包走有预算的完整安装。可变历史 wheel 首次导入需要独立复制预算；已完成的受管下载直接提升为共享材料，不再复制压缩包。后续操作与新实验继续复用匹配材料。

普通命令与推理服务只读挂载已登记环境，不修改共享硬链接文件的权限。创建或删除一个环境的链接，保留其他环境的路径和内容。升级先在私有目录构建新代次，确认当前环境的命令和服务已退出后才替换；验收失败恢复保留的旧代次。`make-writable` 仅复制并原子替换已登记的指定包文件，后续复验更新修改后的内容摘要；修改文件不会成为未经修改的原版本共享材料。

只读历史扫描列出服务器专属实验目录中的已安装元数据和缓存 wheel。检查只读取候选元数据；获取材料时完整验证 RECORD，并单独扫描 wheel，避免已安装元数据先耗尽候选预算。解析器先使用已验证的本地 wheel 目录并禁用索引，仅在本地材料不能满足要求时才在线解析。可变安装内容保持原样，不能直接成为共享内容来源。wheel 必须匹配锁定摘要及目标标签后才能导入；私有源码构建另外绑定编译器、平台和 GPU 配置。仅顶层 wheel 元数据识别发行包，合法的嵌套第三方元数据保留。未知、不完整或损坏来源保留诊断；`legacyEntryLimit` 默认限制 100000 个访问条目，有界扫描会标注结果不完整。

<a id="space-and-cleanup"></a>
## 空间与清理

`experimentStorageUsage(id)` 返回节点测量值和原检查时间，本机在 `$DSH_HOME/aspera-environments/<experimentId>/storage.v1.json` 保存独立版本 1 副本。优先使用已认证控制接口；控制进程停止时，可通过只读 SSH 检查原保存目录。读取失败保留带时间的本机副本和连接错误，概览区分远端测量、SSH 读取与离线副本。

引用随远端环境存在而保留，包括实验结束和仅删除本机记录。确认远端实验删除后，还需确认专属运行目录和清理目录消失，才能释放引用。共享包必须没有登记引用及外部硬链接，才进入候选；引用对应文件缺失时要求核对，不自动解除引用。

安装成功后通过归属检查清理私有下载与构建文件，私有 uv 缓存通过 `uv cache clean` 清理。已验证材料继续保留供复用。存储治理发布保留唯一已验证 wheel，预览无引用受管对象、已确认退出的私有文件，以及有保留副本的已验证重复材料。历史候选需要明确选择；未决引用阻止回收。`cleanupExperimentCache(request)` 绑定节点、预览摘要与操作 ID，拒绝引用变化和活动命令／服务。受管恢复与清理可在执行空间余量不足时运行，仍核对挂载和归属。已有非受管缓存和旧环境继续保留。

显式清理预览将空闲且归属明确的 pnpm 仓库与带标记的 uv 缓存列为 `manager-cache` 候选。Agent 选择后由固定版本包管理器回收，保留已安装环境，并排除活动、被引用或越界的缓存路径。预览变化时保存带具体原因的受阻结果；刷新预览并使用新操作 ID，不能重复提交过期删除。

显式选择 `input-duplicate` 后，仅合并已确认终态并释放资源的实验中内容相同、已认证的 wheel 输入快照。保留路径和字节，通过同挂载硬链接共享，权限及所有者必须相同。当前实验、退出未决、活动来源引用、外部别名、文件变化及跨挂载均排除。独立 `input-sharing-v1` 回执保留原文件身份与时间；链接时间可能改变。共享输入锚点不代表 wheel 已通过安装验收。清单 `inputSharingVersion: 1` 要求 `managed-input-sharing-v1`。

`release-asset-duplicate` 用于显式合并空闲封闭发布中已知且不可变的 LibreOffice wasm/data 和终端 PDB 资源。排除选定发布、安装器、活动进程映射或文件描述符、归属变化及外部别名。所有发布路径与字节保留；`release-asset-sharing-v1` 保存原身份和替换回执。`releaseAssetSharingVersion: 1` 要求 `managed-release-asset-sharing-v1`；该能力不允许删除发布或任意重写包。

清理使用 `O_PATH` 和 `O_NOFOLLOW` 打开目录及条目，从 `/proc/self/fdinfo` 读取当前 `mnt_id`，通过保留的目录描述符执行相对删除。同一 overlay 挂载允许不同 `st_dev`；真实跨挂载、同盘 bind mount、目录替换和身份不可读仍阻止清理。内部符号链接仅删除链接，不访问目标。诊断保留路径、检查阶段、挂载 ID 和设备号，保存的挂载 ID 不作为后续操作授权。

验收、引用保存、代次发布和临时清理分别记录。发布成功后，普通删除失败保留已验收环境及独立版本 1 待清理记录；安全检查失败或进程结果未决仍阻止执行。普通命令和服务使用只读空挂载隐藏残留操作目录，防止临时硬链接成为共享包的可写入口。包和材料引用保留至实际清理完成。概览区分“环境已验收，临时文件待清理”和未验收环境。

<a id="recovery-and-compatibility"></a>
## 恢复与兼容

即使原回执已确认退出，恢复仍重新核对发布、目录代次及私有残留。独立版本 1 恢复记录保留原回执和时间；已发布代次保留供复验，中断替换存在原代次时恢复原代次。没有可用代次的失败阶段保留为证据，允许在原环境身份下重新准备。Agent 随后调用 `prepare_experiment_environment` 核验解释器、用户级包隔离、依赖、导入及所需 CUDA，缺失依赖仍在原环境身份下补齐。重复恢复读取保存结果，代次或回执身份变化返回冲突。

选定固定清单含 `asperaEnvironmentTools.cleanupVersion: 1` 时，复用控制进程及交接前还必须确认 `managed-environment-cleanup-v1`。旧实验保留原发布与结果；确认资源释放后，复制实验使用修复后的发布和可复用的已验证材料。

清单 `asperaEnvironmentTools.installVersion: 3` 要求具备 `managed-environment-install-v3`，提供独立固定 pip 工具环境及包冲突重试检查；版本 2 仍按自身能力读取。启动旧固定发布的控制进程和 worker 时省略 pip 配置，复用时不能由 v3 控制进程替换旧发布的安装实现。独立版本 1 运行记录保存原期限、停止原因、实际退出与准入释放；生效依赖保留原请求身份。运行、启动、回执和复用记录纳入本机归档及实验专属文件清理。概览按程序记录时间区分基础解释器已验收、依赖已验收、安装中和退出核验。已有固定发布需要确认释放资源后复制为新实验。

结构化共享文件冲突保存于 `environment-operations-v1/<operationId>/failure.v1.json` 和回执的可选 `failure`。检查绑定环境、规范化要求、安装实现、Python／工具版本、平台、沙箱、GPU 配置和保留代次。相同输入在创建安装工具／训练环境或解析依赖前停止；要求改变后，如果仍选中相同冲突 wheel 身份，则在获取材料和安装前停止。更换操作 ID、切换 create/install 或调整无关依赖不能修复冲突。相关输入改变后允许重新核验，原失败记录及进程退出保护继续保留。暂时连接故障和未分类错误沿用现有恢复行为。

环境清单、包引用和操作回执使用独立版本 1 文件。请求与内容绑定并支持重复读取，服务器共享包锁串行协调安装、发布和回收；持久准入标记在修改期间阻止实验启动新命令。引用可靠落盘后才发布就绪状态，磁盘或写入失败保留已有记录。退出结果未决时保留标记，直到 Linux 进程组和主机启动证据确认原操作结束；恢复保留的代次，或要求对已提交的新代次重新验收。清理中断时保留剩余候选并要求重新预览，不盲目重复删除。

`inspect_experiment_environment` 保持只读，安装期间可以读取原子保存的计划，清理资格仍待确认。`recover_experiment_environment` 核对原操作，不接受模型指定 PID 或路径。独立启动记录区分准备启动、正在启动、已启动、拒绝启动和已退出，待处理状态保留原时间。启动前拒绝会记录并收尾；缺少命令或启动证据的旧操作继续受限并要求核查。执行 Agent 同时获得 `preview_experiment_cache_cleanup` 和 `cleanup_experiment_cache`；失败后保留原环境，不创建另一安装目录。

本机在发送删除请求前可靠保存清理回执。重启恢复只读取原操作状态，不再次发送删除；退出仍未确认时阻止远端实验删除。仅删除本机记录时停止本机读写，不释放远端包引用。

能力标识 `managed-environments-v1` 与 `managed-environment-reuse-v1` 分别声明已认证环境操作和安装前复用/恢复。固定清单含 `asperaEnvironmentTools.reuseVersion: 1` 时，复用控制进程及交接前必须确认后一项能力；旧控制进程即使健康也需经现有空闲核对及受控修复。计划、材料索引、锁定结果和启动记录使用独立版本 1 文件。提交协议 4、本机存储域 6、Session 事件及原提交内容保持不变。旧实验保留原固定发布及环境；请求、诊断和复验通过原执行 Session 工具事件记录。本机删除等待 Host 读写结束，确认远端删除后才释放引用。

Linux 文件系统测试与无密钥 worker/Web 回放分别验证对应本机机制。真实 4090-1 环境导入、文件身份及磁盘增量要求服务器可连接；CUDA 验收还要求 GPU 可用。无法执行的项目继续记录为待验证。
