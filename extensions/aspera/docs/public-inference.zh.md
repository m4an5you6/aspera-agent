# 公网推理验收

[English](public-inference.md) | 中文

## Agent 与程序职责

执行 Agent 使用 `start_inference_service(publish=true)` 和节点已保存的映射登记自己的回环服务。本地健康状态通过后，调用 `verify_inference_service`，传入 `server_id` 及包含 `operationId`、`serviceId`、`maxTokens`（1–256）的 JSON。工具内部等待程序验收，不暴露凭据，也不创建额外 Agent。

本机 Host 检查登记的公网 URL，因为节点可能无法回访自己的平台映射。程序核对带新 nonce 的服务／实验身份、无凭据与错误凭据的拒绝、登记模型清单，以及固定无敏感测试提示的真实生成回答。不发送实验 Goal、聊天历史或任意 Agent 提示。拒绝重定向，并按配置限制响应大小。Agent 阅读这些观察后决定下一步。本地健康状态和 Agent 自写报告均不能独立证明公网访问有效。

Host profile 配置 `publicServiceVerificationRoute` 默认为 `direct`：验收使用独立连接处理登记 URL，不改进程全局代理。需要沿用现有 HTTP 代理策略时选择 `inherit`。两种方式均保留 TLS 校验、凭据处理和重定向拒绝。结果记录连接方式及有限长度的传输错误代码，不含代理凭据。更改连接方式不会重放已经保存或结果未决的生成请求。

## 使用推理页面

实验详情和侧栏共用同一服务视图。选择当前服务后，可读取地址、登记模型 API 名称及独立的进程／外部观察。进程时间表示状态更新，外部检查保留各自原时间。读取失败保留已有内容，不能确认当前健康。已释放尝试收在默认折叠的历史中，包括启动失败；未释放的异常服务仍属于当前服务。

直接调用模型提供 OpenAI 兼容的 `POST /v1/chat/completions` 模板，带入登记模型和简短消息。服务健康检查使用认证网关的 `GET /_aspera/health`，不触发生成。默认选择 PowerShell：直接赋值密钥，使用 `ConvertTo-Json` 序列化请求，再通过 `Invoke-RestMethod` 发送 UTF-8 字节；Windows PowerShell 5.1 使用 `Invoke-WebRequest`，先把响应字节按 UTF-8 解码，再解析 JSON，兼容未注明字符集的回复。保留适用于 Bash 的 cURL。可以替换 `YOUR_API_KEY`，或点击“复制命令（含密钥）”获取当前凭据并复制可直接运行的命令。缺少外部映射或模型身份时，对应示例不可用，不补造数值。查看、切换和复制示例不会发送模型请求，也不表示生成验收通过。

API Key 的查看或复制动作会明确获取该服务的调用凭据。状态待确认时仍允许发起该请求，由接口重新核对服务身份；取得密钥不会清除状态错误。已释放、正在停止或未发布外部地址的服务不能获取密钥。页面模板、普通快照和非密钥表单状态均不包含密钥。“复制命令（含密钥）”仅将凭据放入本次请求的剪贴板文本；切换服务、示例或页面后丢弃待处理的复制回复。切换服务或页面会清除已展示密钥。请求调试使用 Aspera 连接，默认采用登记的后端健康路径。每项服务独立保留 GET／POST 输入和结果。受管请求成功不能证明外部网络可达。

管理 → 停止服务先说明调用影响，再提交已有停服操作。页面等待资源释放确认后才移入历史；回复丢失时继续待核验。模型文件、结果和日志保留。服务操作始终使用实际所属实验，包括展示在原实验下的恢复任务。

## 替换服务

后端需要纠错时，执行 Agent 调用 `stop_inference_service`，传入授权的 `server_id` 和原 `service_id`。认证节点核对实验归属，关闭该服务的公网网关、停止自有进程并检查清理结果。成功停服保留模型文件、checkpoint、环境和日志。Agent 等待 `released=true` 后，使用新的服务 ID 启动修正后的命令，再次验证本地健康与公网访问。原服务 ID 始终绑定原命令，重复启动不会重新运行已停止记录。退出未确认或回复丢失时，应查询或重复原停服请求，不能启动替代服务或通过普通命令向 PID 发信号。

## 复用保留断点恢复推理

独立推理任务可以使用保留的 adapter，无需重新激活来源实验。Agent 使用授权服务器和原实验 ID 调用 `inspect_inference_checkpoints`，选择所需的原生步数，再使用返回的断点 ID 和持久操作 ID 调用 `prepare_inference_checkpoint`。节点要求来源分配、命令和服务均已释放，断点已经封存，目录归属及文件、挂载身份保持一致。摘要计算在节点修改锁之外执行；发布前重新核对这些观察。

快照只包含 `adapter_config.json`、`adapter_model.safetensors` 和 `trainer_state.json`。程序建立同盘硬链接，不修改来源、不下载权重；跨盘请求明确失败。命令和登记服务均以只读方式挂载快照。后端命令使用返回的 `adapterPath` 加载，登记服务的 `model_path` 使用工作区相对路径 `snapshot.destination`。不包含优化器和 scheduler 文件。这是推理快照，不能作为新训练证据。原结果和固定发布保持不变。Agent 自主选择并运行推理，再请求相同的独立公网检查。

发布中断后，普通可写命令和服务启动被阻止。使用完全相同的操作 ID 恢复已保存请求，其他操作不能绕过。完整快照拥有独立文件链接，即使来源别名随后移除，快照仍可读取。删除当前实验只删除它的别名与记录。快照发生变化时保持阻塞，不静默刷新身份。

转发请求体时保留已知且合法的 Content-Length，使后端可以按固定长度读取，无需为此实现 chunked 解码器。未知长度的上传继续流式传输；声明长度和实际字节量均受限制，公网 Bearer 密钥不会转发给后端。

## 等待与恢复

节点先保存独立版本 1 请求，再由 Host 认领。请求身份、服务命令、固定发布、模型名、URL 和原期限保持固定。Host 先保存有限大小的结果，再提交远端。重复请求返回原结果；已认领的生成请求不会自动重新发送。重启 Host 后可以重新提交已保存结果，无需再次生成。回复丢失且证据无法恢复时保持未决。轮询沿用现有 finalization 限制，服务请求超时配置决定原期限。

Host 成功观察保留原检查时间，与节点回访公网的路由失败分别记录。当前进程身份、本地健康和资源释放检查继续生效。完成实验前，每个活动公网服务都必须具备程序拥有的认证与生成回执。中断和删除沿用现有释放控制停止服务；删除先等待本机验收停止，再移除副本。

成功完成时，执行结果保存通过验收并进入服务状态的确切服务器／服务身份。监控和重启恢复只跟踪这些身份，已释放的启动失败记录作为历史保留，不会使健康替代服务终止。已接纳服务失败或身份缺失时，监控仍判失败；接纳记录缺失时保留占用，不猜测或重启服务。

## 记录与兼容

持久类型确认：`ServiceVerification` 使用独立版本 1 记录，位于远端实验的 `service-verifications-v1` 和本机 `$DSH_HOME/aspera-service-verifications/<experimentId>`。保存结果与 Session 事件不含凭据。节点记录纳入离线归档与实验清理。协议 4、fleet 第 6 代、Session 数据和旧提交保持不变。

`asperaServiceVerificationVersion: 1` 要求准备与控制进程复用时核对 `public-inference-verification-v1`。旧实验保留原发布；确认释放后再复制实验使用新实现。原可执行文件可继续加载更新后的桌面资源。

`asperaServiceLifecycleVersion: 1` 要求复用控制进程前核对 `inference-service-lifecycle-v1`。工具使用既有协议 4 停服操作和服务记录，不引入新的持久数据代次。更新桌面资源不会改变运行中 Agent 的固定工具定义。

快照持久类型确认：独立版本 1 的 `InferenceCheckpointSnapshot` 记录保存在每个实验的 `inference-checkpoints-v1` 下，绑定不变的操作请求、来源实验／命令／原生步数、文件摘要和身份、目标目录、发布状态及原时间。记录纳入离线归档和实验删除。`asperaInferenceCheckpointVersion: 1` 要求 `inference-checkpoint-snapshots-v1`；桌面更新不会给旧固定发布增加这些工具。不改变 Session 或 fleet 存储代次。
