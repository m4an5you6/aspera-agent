# 状态与接口

[English](state-and-api.md) | 中文

## 概要

Aspera 扩展 `0.2.0` 写入协议第 `2` 代，并读取已发布的第 `1` 代而不改变内容摘要和原限制。生成的 DSH Remote 使用 `aspera` 命名空间；新的认证控制通信使用 `/aspera/v2`。准确字段和带标记的 ID 见[协议](../packages/experiments/src/cluster-protocol.ts)及[派发类型](../packages/dispatch/src/types.ts)。

<a id="persistent-ownership"></a>
## 持久归属

| 归属方 | 存储域/版本 | 持久记录 |
| --- | --- | --- |
| 管理 Host | `aspera_fleet` / `2` | 服务器登记、固定调度主机 ID、固定派发要求和完整回执 |
| 远端调度主机 | `aspera_queue` / `2` | 接收顺序、计划、确认、资源分配、执行身份、进度和服务 |
| 节点控制服务 | `aspera_node` / `2` | 节点分配、命令身份、清理证据和登记的服务状态 |

这些存储域声明版本 `2`，兼容读取版本 `1`。旧可选限额仅保留在读取接口中，不出现在新请求。新版本不会执行旧的排队或待确认任务；已分配任务保持原发布版本，直到完成并确认清理。新的控制服务拒绝替换活跃的不兼容进程。不修改 DSH Session 格式或事件内容：问题和回复使用现有工具调用及结果，续行使用记入日志的 Goal 编辑。

提交固定目标、服务器定义、节点权限、输入及摘要、执行模式、DSH/扩展版本和发布身份，派发记录同时固定模型提供方、模型及推理强度。协议第 `2` 代没有任务总时长、总命令数、总轮数或服务总时长预算。同一实验 UUID 的相同内容可以幂等重试，不同内容使用该 UUID 会失败。修改服务器或模型设置只影响新实验。上传重试的字节必须相同，所有声明的上传大小匹配后才能确认输入。

调度服务先写入归属，再调度。队列记录丢失但留有执行证据时，需要操作人员核对，不能重新提交启动。重启后已确认清理的命令可以释放节点，任何未确认的受管进程范围继续占用节点。修复资源记录前，在相关节点检查并停止不明进程；页面不提供强制释放按钮。

<a id="receipts-and-goals"></a>
## 回执与 Goal

`receipt` 保留首次接收的完整回执，`latest` 保存当前远端记录。两者均包含固定 `handover` 值**本机派发完成，远端实验已接管**。接收表示源码、输入及必要凭据已移交，调度主机已承担任务，不表示训练已经开始。资源分配和 Agent 启动后，补充执行 Session/Goal ID。

Host 先持久保存完整回执，再追加接管消息并完成派发 Goal。完成时比较原 ID 和版本号，旧回执不能完成已编辑或已替换的 Goal。浏览器实验使用独立 Session，普通对话中的 `/goal` 保持原有语义。

半自动确认绑定显示的计划版本。同一版本重复确认是幂等操作，不同版本会失败。提交的要求不能原地修改；新的要求通过新实验重新确认。全自动策略确认与用户确认分别记录。

半自动问题绑定实验、Session、工具调用和固定的问题版本。调度服务先持久保存问题，再暂停 Goal；已有受管进程继续受到监控。回复先校验并保存，再交付原调用并恢复同一 Goal。相同回复重试是幂等操作；冲突、过期问题以及已取消或中断的任务不能恢复执行。重启将待回复问题报告为中断并使其过期，不重放工具。

<a id="api-consumers"></a>
## 接口使用方

Web 页面或外部 DSH 客户端使用 [AsperaRemote](../packages/dispatch/src/index.ts) 及生成的 `@aspera/dispatch/remote` 描述。普通方法涵盖服务器及密码写入、输入暂存、创建、查询及刷新、计划确认、`answerExperimentQuestion`、取消、日志、文件和服务访问及停止。`watch` 持续提供包含问题的最新持久快照，重连后客户端接收最新快照并保留各来源的字节游标。Agent 派发工具与这些方法共用 `ExperimentFleet`。新的 API 不包含默认预算和预算提交参数。

`ClusterQueue` 使用验证持久数据的 `ExperimentTable` 和管理进程的 `ClusterExecutor`。`ExperimentFleet.open` 接受完整的 `FleetDriver`，生产实现采用密码 SSH 和主机密钥校验。一个提供方同时负责移交、探测、凭据和认证操作。CPU 提供方仅存在于明确的测试夹具中，不进入发布文件。

控制接口需要私有 bearer 凭据，只监听回环地址。Host 和调度主机通过受管理的 SSH 连接访问。密码查询只返回是否配置及可写，密码由 DSH 凭据服务保存，并复制到受限的调度主机文件，以便控制分配的节点。模型要求、回执和浏览器查询均不返回明文。

<a id="logs-outputs-and-services"></a>
## 日志、产物和服务

读取由实验、来源或节点、流代次和字节位置确定。返回原始 base64 字节、下一位置、EOF 和重置标记。日志缺失或轮转会重置游标并明确展示，独立的 UTF-8 解码器重建节点日志。会话封装包含 Session ID 和来源，规划与执行中相同的序号不会混合。不完整的 JSONL 行等待后续内容。

输出接口列出相对路径、来源节点、大小和更新时间。下载使用一次性过期票据和有界读取，拒绝路径越界、符号链接逃逸及文件代次变化。下载断线会中止上游读取，默认不同步文件内容。

服务具有独立 UUID、所属实验及节点、模型路径、命令身份、回环端口、健康接口和清理状态。仅旧记录带有服务截止时间。启动要求端口未占用，健康要求受管进程存活且实际 HTTP 检查成功。访问支持有界的私有 GET/POST 请求，不自动公开到公网。停止或取消后，确认受管进程清理才释放资源；异常退出为终止状态，不自动重启。
