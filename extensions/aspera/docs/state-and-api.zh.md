<a id="persistent-ownership"></a>
## 持久归属

| 归属方 | 存储域/版本 | 持久记录 |
| --- | --- | --- |
| 管理 Host | `aspera_fleet` / `3` | 服务器偏好、最近 SSH 探测、固定调度主机、存储选择、派发要求和回执 |
| 远端调度主机 | `aspera_queue` / `3` | 接收顺序、计划、确认、分配、执行身份、进度和服务 |
| 节点控制服务 | `aspera_node` / `3` | 节点分配、命令身份、清理证据和登记的服务状态 |

这些数据域声明版本 `3`，兼容读取 `1`、`2`。协议 `1` 保留扩展版本 `0.1.0` 及原限制，协议 `2` 保留 `0.2.0`。旧在途任务使用原运行时；任务结束并确认清理后才替换不兼容的控制服务。不修改 DSH Session 格式和事件定义：探测、存储选择、接管、问答均使用现有的消息、工具及 Goal 操作记录。

服务器配置偏好与已解析部署分开保存。创建时固定目标、服务器、模型选择、模式和策略；准备时固定输入摘要、挂载身份、控制／发布／工作目录、选择理由及已验证的内网地址。协议 `3` 不设任务总预算。同一 UUID 和内容可幂等重试，内容变化则拒绝。第 3 代中断准备复用已保存目录，Session 缺失、挂载、输入或发布变化时明确失败；旧版未完成准备需复制为新实验。

调度服务先写入归属，再调度。队列记录丢失但留有执行证据时，需要操作人员核对，不能重新提交启动。重启后已确认清理的命令可以释放节点，任何未确认的受管进程范围继续占用节点。修复资源记录前，在相关节点检查并停止不明进程；页面不提供强制释放按钮。

<a id="receipts-and-goals"></a>
## 回执与 Goal

`receipt` 保留首次接收的完整回执，`latest` 保存当前远端记录。两者均包含固定 `handover` 值**本机派发完成，远端实验已接管**。接收表示源码、输入及必要凭据已移交，调度主机已承担任务，不表示训练已经开始。资源分配和 Agent 启动后，补充执行 Session/Goal ID。

Host 先持久保存完整回执，再追加接管消息并完成派发 Goal。完成时比较原 ID 和版本号，旧回执不能完成已编辑或已替换的 Goal。浏览器实验使用独立 Session，普通对话中的 `/goal` 保持原有语义。

半自动确认绑定显示的计划版本。同一版本重复确认是幂等操作，不同版本会失败。提交的要求不能原地修改；新的要求通过新实验重新确认。全自动策略确认与用户确认分别记录。

半自动问题绑定实验、Session、工具调用和固定的问题版本。调度服务先持久保存问题，再暂停 Goal；已有受管进程继续受到监控。回复先校验并保存，再交付原调用并恢复同一 Goal。相同回复重试是幂等操作；冲突、过期问题以及已取消或中断的任务不能恢复执行。重启将待回复问题报告为中断并使其过期，不重放工具。

<a id="api-consumers"></a>
## 接口使用方

使用 [AsperaRemote](../packages/dispatch/src/index.ts) 及生成的 `@aspera/dispatch/remote` 描述。普通方法包括服务器／密码保存、不调用模型的 `probeServer` 探测、输入暂存、创建、`retryPreparation`、刷新、确认、问答、取消、日志、文件和服务。`watch` 回传保存的探测信息、准备阶段、目录及远端回执；重连先读取当前记录，日志保留分来源的字节游标。Agent 工具共用 `ExperimentFleet` 准备服务。

`ClusterQueue` 使用验证持久数据的 `ExperimentTable` 和管理进程的 `ClusterExecutor`。`ExperimentFleet.open` 接受完整的 `FleetDriver`，生产实现采用密码 SSH 和主机密钥校验。一个提供方同时负责移交、探测、凭据和认证操作。CPU 提供方仅存在于明确的测试夹具中，不进入发布文件。

控制接口需要私有 bearer 凭据，只监听回环地址。Host 和调度主机通过受管理的 SSH 连接访问。密码查询只返回是否配置及可写，密码由 DSH 凭据服务保存，并复制到受限的调度主机文件，以便控制分配的节点。模型要求、回执和浏览器查询均不返回明文。

<a id="logs-outputs-and-services"></a>
## 日志、产物和服务

读取由实验、来源或节点、流代次和字节位置确定。返回原始 base64 字节、下一位置、EOF 和重置标记。日志缺失或轮转会重置游标并明确展示，独立的 UTF-8 解码器重建节点日志。会话封装包含 Session ID 和来源，规划与执行中相同的序号不会混合。不完整的 JSONL 行等待后续内容。

输出接口列出相对路径、来源节点、大小和更新时间。下载使用一次性过期票据和有界读取，拒绝路径越界、符号链接逃逸及文件代次变化。下载断线会中止上游读取，默认不同步文件内容。

服务具有独立 UUID、所属实验及节点、模型路径、命令身份、回环端口、健康接口和清理状态。仅旧记录带有服务截止时间。启动要求端口未占用，健康要求受管进程存活且实际 HTTP 检查成功。私有访问支持有界的 GET/POST 请求。可选 `inferenceMapping` 将平台 HTTPS 基础地址及映射端口固定在服务器快照中。`start_inference_service(publish=true)` 在映射端口提供 Bearer 认证入口，将 GET/HEAD/POST 流转发到回环地址上的模型；模型端口必须与映射及控制端口不同。节点通过外部地址检查服务／实验身份及随机校验值，独立于本地健康状态保存 `external.state`，拒绝重定向。节点发起的检查不保证所有调用者网络都可访问。服务密钥位于 Agent 工作目录之外的节点私有文件中，不进入回执、日志或 Agent 工具结果，仅操作人员主动调用 Remote `serviceAccessInfo` 时返回。停止、取消及进程退出会关闭对外监听；节点重启不重建身份未经核实的监听器。停止或取消后，确认受管进程清理才释放资源；异常退出为终止状态，不自动重启。
