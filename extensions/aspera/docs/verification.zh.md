# 验证

[English](verification.md) | 中文

## 概要

修改代码、生成的 Remote、依赖版本或发布文件后，运行独立工程的检查。本地夹具无需模型凭据或 GPU，即可验证调度、DSH 接入和服务生命周期，但不能证明 CUDA、真实框架训练或多节点集合通信正确。

## 目录

- [本地检查](#local-checks)
- [GPU 验收](#gpu-acceptance)

<a id="local-checks"></a>
## 本地检查

冻结安装后在本工程内运行。先构建，再运行 profile 检查，使其使用当前的发布产物。

```text
pnpm run build
pnpm run typecheck
pnpm run lint
pnpm run test
pnpm run test:api
pnpm run test:worker
pnpm run test:control
pnpm run test:web
pnpm run test:installed
pnpm run build:desktop
pnpm run test:desktop:api
pnpm run test:desktop
```

lint 使用扩展自己的配置，同时检查 TypeScript 源码和维护脚本。

节点生命周期测试使用已发布的逐记录 JSON 后端，验证合法 run ID、跨实验隔离、重复请求、输出流查询、服务停止及已确认／未确认的重启恢复。`test:worker` 还通过带认证的回环路由记录正式 `run_experiment_command` 调用，使用纯 CPU 进程夹具和实际持久化记录；重复调用只启动一个进程，Agent 工具读取其完整节点输出。

安装恢复检查使用 `installation.spec.ts`、准备／fleet／控制器测试，以及 Linux 下的 `python3 packages/dispatch/tests/installation_executor_test.py`。Python 夹具用专属临时归档及模拟包管理／编译进程运行随包安装执行器，覆盖持续下载、无输出编译、无效心跳、无进展／总时限到期、检查点复用、原材料校验、完整末尾输出及核对身份的取消。不使用模型账户、SSH 服务器或 GPU。真实 Web 回放还覆盖自主来源探测／切换、验收、固定预算、不移动布局且只出现一次的 Toast，以及 `web-installation-recovery-*.png` 明暗／小窗口进度截图。

`pnpm run test:observations:web` 使用真实记录的 CPU Session，验证官方轨迹渲染、自动历史加载、阶段搜索恢复、滚动联动、工具定位日志、阅读历史时继续接收、完整下载及不移动布局的持久 Toast 去重，输出 `observations-*.png` 截图。观测定向测试覆盖完整事件、附件、输出脱敏、游标归属、轮转、缺失文件、实测数据断点及带认证的调度节点回环访问。

现有桌面可在上述检查后仅更新资源。先运行 `pnpm run update:desktop:resources --prepare`，再运行 `pnpm run update:desktop:resources --apply <prepared-directory>`。准备步骤校验冻结依赖与已发布渲染补丁。应用步骤拒绝已变动的外壳或运行时，保存备份，替换 `runtime.asar` 及有变化的外置资源，并在现有构建信息中记录摘要。`Aspera.exe`、桌面外壳文件、用户数据和已提交实验保持原样。该步骤不调用 `build:desktop`，不创建桌面交付目录，不生成 ZIP。正常重启应用后加载新资源；更新器不结束用户进程。

管理测试覆盖串行调度冲突、无重叠提交、密码读取、带时间检查及过时回复。删除测试覆盖显式确认的离线删除、服务器快照保留、未确认地址占用、清理等待时切换、本机清理恢复、删除标记和延迟回复。存储清理使用真实 CPU 文件和模拟 Linux 挂载事实，拒绝归属不符、变化／嵌套挂载与路径越界，保留链接外部内容。真实旧日志文件测试覆盖两个读取方向的截短，保留脱敏处理。Web 回放验证明暗及窄窗口紧凑弹窗、离线删除、关联实验保留、返回筛选、密码、历史硬件及调度选择，输出 `management-*.png` 并将结果记录在派发快照中。

准备测试覆盖程序缺失、发布要求的 Node 范围和固定 pnpm、命名空间权限不足、非零命令、SSH 认证、超时／取消、退出未确认、记录保存失败及未授权服务器。完成必须通过程序验收。重试用例保留协议 4 Session，在本机升级后复用原发布，恢复远端回执，并串行准备共享服务器。Web 回放驱动标准准备 Agent 调用诊断工具，经历下载失败、修复和复验，在派发快照中记录工具序列。

模型夹具创建并恢复并行运行的标准 DSH Agent，通过实际发布的提供商向本机 CPU HTTP 接口发起请求，分别验证各阶段的密钥和模型。同名全局提供商保持原设置，profile 能观察到 Agent 发布、发起者跟踪及释放。提交测试覆盖配置修改、不支持的认证、缺失凭据及私有／公开数据隔离。记录与进程用例覆盖来源绑定游标、不完整尾行、轮转、分页和隔离；浏览器验证覆盖模型选择、关闭待办的持久化及工具定位进程。

单元测试使用独立状态目录、受管进程替身和系统分配的端口，覆盖数据盘／系统盘、未知持久性、手动路径、权限／空间不足、挂载变化、目录归属、准备重试、固定身份、Goal 版本、多网卡选择、单向不通、错误接收端证明及监听器清理，同时保留队列、输入、文件、游标和服务竞争测试。符号链接越界夹具在 Linux/macOS 执行，Windows 跳过。

`test:api` 使用真实派发适配器启动正式管理 profile，通过认证读取旧版服务器登记和实验列表。`test:desktop:api` 使用现有应用目录、升级后的 profile，以及仓库外的中文状态路径，验证同一服务器 API，并通过真实表单保存服务器。两项检查均不创建发布 ZIP，也不替换派发适配器。

`test:worker` 启动正式 worker profile。计划与执行通过已发布的 pi-ai 适配器调用本机 HTTP 夹具，检查保存的认证及实际提供商请求；续行和恢复使用流回放。它检查实际规划及执行工具列表、输入访问拒绝、声明输入读取、框架知识、持久计划及执行记录和 [Session 快照](../scripts/fixtures/worker.snapshot.json)。自动执行 Agent 无法使用通用命令、插件安装或人工等待。续行回放跨过原 128 轮限制，验证所有延长均记入日志，且 Session 和 Goal 不变。步骤上报回放使用实际工具处理遗漏记录、版本冲突、受阻步骤继续及重启读取；步骤全部上报完成但缺少成功命令时，独立验收仍失败。

`test:control` 使用真实存储域启动正式调度和规划 worker，验证真实问题持久化、暂停时模型调用不增长、并发相同回复、拒绝冲突及取消后回复、恢复同一 Goal，以及认证接收、完整接管、不占资源的计划在调度重启后保留、删除暂存输入后的相同重试、拒绝修改内容、拒绝遗留执行及取消。调度启动、问题持久化和回复后规划分别使用独立的 60 秒测试期限。[问题 Session 快照](../scripts/fixtures/control.snapshot.json)记录持久化问题、回复、原工具结果及 Goal 转换。仅因计划等待确认而采用模拟节点清单，不启动 GPU 命令。

`test:web` 使用已发布 Web 装配及生成的 Remote，接入显式 CPU 测试提供者。它验证仅填 SSH 信息保存、不调用模型的连接探测、已记录的 Agent 选盘、保存目录和计划确认、附件、独立 Goal、队列、接管说明及[派发快照](../scripts/fixtures/session.snapshot.json)，并覆盖重连／轮转、会话隔离、下载、真实 profile 中的 HTTP 服务、断线、停止、失败、取消和持久问答。对外推理用例覆盖真实认证网关、流式响应、目标身份不符、取消后的监听器、可选表单字段及仅主动查看才返回的调用信息。概览检查覆盖四个阶段、切换页面后的重试状态、等待决定、节点记录、可展开错误，以及桌面和窄窗口的明暗布局。截图输出到 `.artifacts/`。

[概览检查](../scripts/test-overview.mjs)使用正式组件及显式 CPU 展示夹具，覆盖实际保存计划、双节点、简短错误摘要、折叠的本地化／未知诊断字段、三项关键指标、缺失值、有效／无效训练步数、读取失败时保留上报、停止转圈、旧发布、键盘展开、中英文和响应式明暗布局。`test:web -- --keep-preview` 保留独立测试 profile 供复核，使用测试数据，不代表真实 GPU 验收。

`test:installed` 打包构建产物，在仓库外安装冻结的生产依赖，检查 NodeNext 使用方类型，从安装目录重新打包，并启动正式 profile。检查客户端声明、侧栏注册、用户名及密码字段和实时 Remote 快照。测试需要已安装的浏览器和已填充的 pnpm 缓存；生产派发需要访问配置的依赖包仓库。

## GPU 验收

本次交付没有可用 GPU 服务器。CPU 回放以注入的命令结果验证 Agent 调度，不安装 Linux 依赖，也不能证明沙箱或 CUDA 就绪。GPU 操作人员使用两台互通的 Linux 节点验收，提前信任 SSH 主机密钥，并将密码保存在管理 profile 的私有凭据存储中。

实际探测硬件与 Goal 要求分别记录。目标要求 T4、节点实际为 RTX 4090 时，复制或执行前需要明确决定。复制实验使用修复后的命令记录发布及步骤上报前，必须确认原任务的节点归属及进程清理；不原地替换固定发布。

从缺少 Node、pnpm、Python 或 bubblewrap 的可丢弃登录环境开始，确认准备 Agent 安装符合发布要求的版本，保留安装诊断，并通过真实工作目录、隔离、凭据隐藏、CUDA 和网络探测。再验证命名空间被拒绝、下载不可用及安装中断，记录所需平台操作或核实后的退出状态，不跳过检查。仅升级本机应用后重试协议 4 失败实验，核对其继续使用远端原发布。

1. 探测两台节点，向云服务商核对所选挂载及云盘持久性，并验证卸载／重挂后保留的目录选择。检查双向内网通信，以及 bubblewrap 拒绝外部写入、读取控制凭据和其他实验目录；同时用获准 CUDA 设备执行短计算。
2. 派发不同节点的任务、共享节点的排队任务和一个联合任务。确认固定 rank、实际集合通信和固定框架版本的短训练，检查记录的脚本、环境、参数及实测输出。
3. 接管后断开并关闭管理机器，验证远端调度服务接续排队任务、执行并保存结果，无需管理端在线。
4. 将训练产物加载到登记的回环推理服务中，验证实际预测、健康检查、服务器持续占用、停止清理及排队任务推进。
5. 在排队和服务观察期间重启调度服务，再验证节点失败、取消竞争和回执丢失，确保不重复训练、不改变服务器组、不在确认清理前释放资源。

记录准确的节点、驱动和框架版本、发布身份、命令、日志及评估输出。无法核实的进程身份保持中断状态，等待操作人员核对，不能作为自动重试的验收路径。
