# @deepseek-ai/dsh-experiment-worker

[English](README.md) | 中文

## 概述

experiment-worker 配置以独立进程运行调度、节点和实验 Agent 角色。调度主机持久保存先进先出队列并整组分配服务器；节点拥有受隔离的受管命令。每个接收的实验使用不可变源码版本和独立的会话、Goal、目录；排队回执在开始执行前移交所有权。

## 使用本包

派发器通过 dsh --profile experiment-worker 启动全部角色。控制接口仅监听本机回环地址并要求私有 Bearer 令牌，通过 SSH 传输。Linux 节点需要可用 NVIDIA 设备、bubblewrap 和支持的子进程提供方。远端目录、凭据、运行限制及获准设备来自已校验的部署配置。

互不重叠的服务器组可以并行。每台服务器按调度主机接收顺序同时只执行一个实验。等待任务不占住部分资源，必须全部所需服务器同时可用；不会通过减少节点使任务运行。训练地址缺失或节点两两通信检查失败时停止多机启动并记录错误。

Agent 仅通过所分配节点的工具准备依赖、数据及协同训练程序。节点命令在所属实验工作目录中使用获准 GPU 设备执行，凭据、控制状态及其他实验目录被屏蔽。接收前和执行前均校验输入内容。提问、审批及插件安装被禁用。

取消会终止全部所选节点的受管命令。只有所有节点和执行 Agent 均确认清理后，终态结果才释放该组资源。重启恢复排队任务并核对已有分配；结果不明的训练标记为已中断，不会自动重跑。未确认的进程清理会继续占用资源，等待运维核验。

协议 2 提供接收、状态、取消、按来源隔离的事件和日志游标，以及限定目录的文件读取。排队回执可暂缺执行会话和 Goal 编号，运行记录再补齐。日志游标按字节计数，包含文件标识、重置和结束标记。文件列表给出节点、相对路径、大小和修改时间，内容仅按请求读取。

receiver 角色保留协议 1 及历史记录，直至其活动实验结束；存在活动任务时拒绝空闲关闭操作。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节 — 点击展开</summary>

一个持久记录在分配任何节点前预留完整资源组。幂等哈希将实验编号绑定到完整提交。私有接收校验源码版本、暂存数据和移交凭据后才记录所有权。各节点在启动前保存分配和命令编号，重试不会重复启动同一命令。

Agent 完成时刷新会话，并检查每个所选节点实际结束的命令结果。调度主机单独保存执行清理证据。Agent 观察调度主机代际变化，在调度主机重启后停止；即使 Agent 已退出，清理证据缺失时仍保留占用。

</details>

## 模型体验

### 联合执行要求

#### 模型看到的内容

已记录的初始消息给出目标、稳定节点序号、地址、GPU 信息、输入及允许的工作目录，要求执行一次分布式运行、核验集合通信，并在完成 Goal 前确认实际退出结果和报告输出。

#### Token 影响

各会话保存自己的要求、工具、节点日志和命令结果，增量读取限制单次工具输出量。

#### KV Cache 影响

一个实验内的初始要求保持稳定，变化的命令证据追加到该会话。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- 重启节点若仍有未确认的进程范围，会保留分配并等待运维检查。

- 文件沙箱限制文件和 GPU 设备，不提供完整网络隔离。

- 不支持调度主机故障切换和自动训练重放。
